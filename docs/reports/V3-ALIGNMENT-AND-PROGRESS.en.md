## Follow-up fix: host pointer alignment is not governed by guest page size

`tasks/remote.rs::whole_pages` previously checked both the host pointer and the range length against guest `APV_PAGE_SIZE`. When an ARM guest uses 16 KiB pages and a Linux x86 host uses 4 KiB pages, valid host mappings could therefore be rejected, manifesting as a failure to create an isolated task.

The fix checks the pointer against `platform.vm().page_size()`, while the length continues to satisfy full guest/host page requirements — preserving non-zero, null-pointer, and misaligned rejections. A positive test for host-aligned, non-guest-aligned pointers was added while retaining all existing invalid-input tests, rather than deleting the check or forcing all host memory allocations to 16 KiB.

Local verification: FIFO module 25 passed; both previously failing remote-task tests passed; serial full Core suite: ARM16K 2294/2294, x86 default 2300/2300, both with 0 failures. Because the two test populations differ due to architecture-conditional tests, the difference in total count must neither be treated as an omission nor claimed as independent cross-ISA certification.

Reference Linux `mmap` contract: https://man7.org/linux/man-pages/man2/mmap.2.html . This project's actual evidence rests on the source code, positive and negative test cases, and the regression runs above, rather than relying on documentation authority alone.

## New guest command round-trip

Self-authored ARM64 firmware submits `Nop(30)` and `GetDeviceInfo(58)` to the same Reims Root FIFO:

1. The guest writes a 12-byte header and payload into RAM and posts the doorbell;
2. The Reims host thread consumes the command and writes back the completion stamp;
3. `GetDeviceInfo` writes its output into another guest 16 KiB page;
4. The guest verifies `key1`/`sample-count`, `key2`/bool, the terminator, untouched boundary sentinels, consumed byte counts, and fault flags;
5. After verification completes, the guest closes the FIFO and exits with status 0.

Positive output is `FIFO NOP STAMP PASS` and `FIFO GET_DEVICE_INFO ROUNDTRIP PASS`.

A `NO_DOORBELL` variant of the same firmware omits posting the first doorbell; the guest never receives a completion, fails via bounded polling, and exits with status 1, which the test runner records as the expected negative control. The host runner neither fabricates results nor writes into the guest output buffer.

This closes the "guest command → host consumption → guest RAM result / completion stamp" path. It does not verify draw/compute, shaders, actual pixels, GPU completion synchronization, or IRQ handling, and therefore does not constitute guest GPU rendering, WindowServer, or macOS boot.

Entry point: `make reims-fifo-roundtrip`; source files: `experiments/E11-arm-reims/probe-device-info.S`, `run-device-info.py`; structured results: `runs/v3-fifo-device-info-results.json`.
