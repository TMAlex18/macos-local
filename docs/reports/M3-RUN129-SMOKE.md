# Run129：恢复实验后的试运行（原样启动、登录、关机）

日期：2026-11-10 UTC。标签：`m3-smoke-20261110-129`。

## 运行前写下的预期

- **目的。** 项目交接后，第一次由新的操作者启动已安装系统，确认整套流程可以操作。不测任何新功能。
- **配置。** 与 Run128 相同，但不加 `--webkit-timeout-diagnostic`，也就是普通的 3 秒期限。运行器和 QEMU 二进制没有改动（SHA-256 `4a433616…8a6b4d66`）。
- **预期。** 启动到登录窗口；输入密码后进入桌面；在客体里执行关机；`qmp-lifecycle.json` 记录客体发起的关机，QEMU 以 0 退出。
- **要记录的数字。** 启动到登录窗口的时间（Run128 是 138 秒）、启动到桌面的时间（Run128 是 225 秒）、运行期间宿主 CPU 封装温度的最大值。
- **运行前的保护。** `root.raw` 和 `aux.raw` 已复制到 `private/safety-copies/20261110-before-run129/`，并与原件逐字节比对。

## 结果

预期全部成立。运行从 16:15:32 UTC 开始，持续 613 秒。

| 阶段 | 第一次看到的时间 | 说明 |
|---|---|---|
| 登录窗口 | 150.5 秒 | 140.3 秒时还是 Apple 标志和进度条。Run128 是 138 秒 |
| 提交密码 | 165 秒 | 用 `type-secret` 输入 |
| Dock 和上次会话的窗口 | 235 秒 | Run128 是 225 秒 |
| 菜单栏 | 373 秒 | 285 秒和 345 秒时还没有 |
| 终端恢复完成 | 484 秒 | 在此之前窗口里一直是加载圈 |
| `sudo` 的密码提示 | 556 秒 | 关机命令在 516 秒之后输入 |
| 客体发起的 SHUTDOWN 事件 | 613 秒 | 确认密码后 44 秒 |

- **关机。** `qmp-lifecycle.json` 记录 `SHUTDOWN`，`guest=true`，原因 `guest-shutdown`；QEMU 以 0 退出并被回收，宿主没有请求退出。
- **`results.json` 仍是 `passed=false`。** 错误列表为空，控制器退出码 1。原因与 Run125–128 相同：客体关机后无法再做最终截图。
- **宿主温度。** 每 5 秒采样一次，共 122 个样本：CPU 封装温度最低 53 °C，平均 78.7 °C，最高 96 °C；有 3 个样本达到或超过 90 °C。记录在运行目录的 `host-temperature.tsv`。

## 限定

- **时间只能粗略比较。** 表里的时间是我截图的时刻，不是事件发生的时刻。另外，启动后前 345 秒里我的等待脚本有一个忙等循环，占满了宿主的一个逻辑核心（共 20 个）；之后已改成阻塞等待。
- **Safari 没有测。** 上次会话的 Safari 窗口被自动恢复，从 345 秒到关机前一直是白页。本轮没有收集 WebKit 日志，不能归因。
- **文件系统是否干净卸载没有证明。**

## 对后续实验的影响

- 登录之后要等大约 6 分钟，恢复出来的终端才能输入。恢复会话占了这次运行的大部分时间。
- 每次启动都会自动恢复 Safari，而且恰好发生在系统最忙的时候。做 Safari 首次加载的计时实验之前，应当先让 Safari 不被恢复，并等系统空闲下来。
